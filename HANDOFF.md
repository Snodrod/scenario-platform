# Scenario Platform — Session Handoff

Прочитайте этот файл в начале новой сессии, чтобы не терять контекст. Это полная история проекта на момент переключения контекстного окна.

## Что это за проект

Платформа для совместной работы над сценарием и раскадровкой: пишешь/импортируешь сценарий →
LLM разбивает на сцены и кадры → генерируешь изображения для кадров → приглашаешь клиента,
он комментирует и утверждает → экспортируешь в PDF. Для DornProductionStudio (канал Dops media),
но сделано как отдельный продукт с собственным доменом в перспективе.

## Что полностью готово и работает

1. Auth (magic link), проекты, роли (owner/co_writer/client/viewer)
2. Редактор сценария + AI-разбивка на сцены/кадры (провайдер на выбор: Gemini/OpenAI)
3. Раскадровка: карточка кадра с полями (реплика, эмоция и подача, ТЗ к монтажу, звук,
   VO-текст для ElevenLabs), генерация картинок (Pollinations по умолчанию/OpenAI/Nano Banana),
   выбор соотношения сторон и качества, лайтбокс по клику на картинку, сквозная нумерация кадров
4. Библиотека персонажей с референс-изображениями
5. Комментарии (реалтайм) на кадрах
6. Команда: приглашение по email, роли, **удаление участников**, **повторная отправка приглашения**
7. Импорт сценария: файл (PDF/DOCX/TXT), публичная ссылка на Google Doc, Google Drive
   (OAuth, не настроен ключами, но код готов), **Notion — с умным определением, если в
   документе уже есть готовая раскадровка** (см. ниже)
8. **Умный Notion-импорт**: если страница Notion уже содержит структуру
   «КАДР NN · таймкод · длительность · теги · статус» + картинка + блоки
   Озвучка/Эмоция и подача/ТЗ к монтажу/Звук + тоггл с VO — платформа парсит это НАПРЯМУЮ
   в сцены/кадры с картинками (перезаливает в Supabase Storage), а не просто тащит текст.
   Проверено на реальной странице пользователя: 8 сцен, 87 кадров, всё распозналось.
9. Массовое внесение правок: вставляешь текст правок → LLM раскидывает по кадрам как комментарии
10. Экспорт в PDF (кириллица работает — шрифт Noto Sans, поля не наслаиваются друг на друга)
11. RLS полностью прожесточена (см. миграции ниже), advisors чистые (кроме двух намеренно
    оставленных WARN — is_project_member/project_role доступны для authenticated по RPC, это
    осознанное решение, т.к. без этого не работает RLS)

## Важные уроки / грабли (не наступать повторно)

- **Самоссылающаяся RLS-политика ломает `INSERT ... RETURNING`**: `SELECT`-политика на
  таблице X не должна вызывать функцию, которая сама делает `SELECT` из X — ловили именно
  на `projects` (is_project_member(id) внутри политики на projects). PostgREST/supabase-js
  всегда делает `INSERT...RETURNING` для `.insert().select()`, поэтому это ловится сразу же
  на создании первой записи. Исправлено — сравнение `owner_id` напрямую вместо рекурсии.
- **Функции в Postgres**: `GRANT EXECUTE` по умолчанию достаётся `PUBLIC` при создании —
  `REVOKE ... FROM anon` не работает, если грант пришёл от PUBLIC. Нужно `REVOKE FROM PUBLIC`
  + `GRANT TO authenticated` явно.
- **@react-pdf/renderer**: НЕ ЛЮБИТ голые React-фрагменты `<>...</>` — вёрстка едет/накладывается
  друг на друга при длинном тексте. Всегда используйте `<View>` вместо фрагмента.
- **@react-pdf/renderer + кириллица**: базовые PDF-шрифты (Helvetica и т.п.) не умеют в
  кириллицу вообще — нужно регистрировать свой шрифт (сделали Noto Sans, лежит в `public/fonts/`,
  резолвится через `process.cwd()`, не через bundler-relative путь).
- **Content-Disposition с кириллицей** ломает HTTP-заголовки (ByteString restriction) —
  нужен ASCII fallback + `filename*=UTF-8''...` (RFC 5987).
- **Vercel «Sensitive» переменные окружения** — write-only, их нельзя посмотреть после
  сохранения (там просто placeholder). Если скопировать замаскированное отображение
  («eyJhbGci••••») вместо реального значения — получите литеральные символы «•» в самом
  значении. Ловили именно так на ANON_KEY — час убили на диагностику через monkey-patch
  `window.fetch` в браузере, чтобы увидеть код символа 8226 (bullet) в реальном заголовке.
- **`NEXT_PUBLIC_*` переменные вшиваются в момент СБОРКИ**, не читаются в рантайме — если
  добавили/поменяли переменную после того, как прошёл билд, нужен новый билд (обычный
  Redeploy это делает, но если сайт всё равно падает — проверяйте реальное содержимое
  переменной, не только факт, что она "добавлена").
- **pdf-parse v2** — новый мажорный API, не как в v1: `new PDFParse({data}).getText()`,
  а не `pdfParse(buffer)`. И pdfjs-dist (внутри) ломается под Turbopack-бандлингом воркера —
  нужен `serverExternalPackages: ["pdf-parse","pdfjs-dist","mammoth"]` в `next.config.ts`.
- **Notion API rate limit** — анонимные/наивные последовательные запросы по дереву блоков
  очень медленные (2.6 минуты на 400+ блоков). Решение — `mapWithConcurrency` с лимитом ~6
  параллельных запросов + retry на 429 с уважением `Retry-After`.
- **Модели Gemini "протухают"** — `gemini-2.5-flash` для новых ключей теперь 404 ("no longer
  available to new users"), актуальная на момент написания — `gemini-3.6-flash` (текст) /
  `gemini-3.1-flash-image` (картинки, но 0 free quota). Проверяйте реальным вызовом API
  перед тем как полагаться на конкретное имя модели — в этом проекте они меняются быстро.
- **Проверять «подключил ли SMTP» надо через логи, не на слово**: пользователь был уверен,
  что настроил Resend SMTP в Supabase — на деле письма продолжали идти через дефолтный релей.
  Единственный надёжный способ проверить — `query_logs` (source `auth_logs`) на события
  `mail.send`, смотреть поле `mail_from`: если это `noreply@mail.app.supabase.io`, кастомный
  SMTP не активен, что бы ни показывал UI дашборда. Так же не путайте `429 email rate limit
  exceeded` (обычный 60-секундный кулдаун между /otp запросами, если кликнуть повторно раньше
  минуты — это нормально) с фактическим отказом SMTP.
- **Каждый `await res.json()` без try/catch — потенциальный краш всей страницы**: любое
  необработанное исключение в API-роуте (например, отсутствующая env-переменная) возвращает
  пустое/HTML тело вместо JSON, и `res.json()` падает с криптоошибкой вместо понятного
  сообщения. Есть общий хелпер `src/lib/fetch-json.ts` (`fetchJson()`) — используйте его
  везде вместо голого `fetch()+.json()`.

## Общий паттерн работы в этой сессии

- Перед тем как объявить фичу готовой — проверяли её реальным вызовом (curl/скрипт/round-trip

  СРАЗУ, и синхронно обновлять `supabase/schema.sql`, чтобы файл оставался источником правды
  для новых установок.
